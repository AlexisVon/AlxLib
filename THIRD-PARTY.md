# Third-party components and licenses (THIRD-PARTY)

AlxLib itself is MIT (see `LICENSE`). This file lists the third-party components that **actually enter the deliverables**.

> **This software is based in part on the work of the Independent JPEG Group.**
>
> Linking libjpeg-turbo statically makes the IJG license require that sentence to appear in the
> documentation — and this library does exactly that (`jpeg_*` are defined symbols in
> `bin/libalxcore.so`, not a dynamic dependency).

The inventory runs along three axes: **link-time** (compiled into `bin/libalx*.so` / `bin/libalxlib.a`), **asset-level**
(shipped with the source repo, invisible to `nm`), and **build-time, self-provided**
(the upstream source packages and the prebuilt Windows libraries, see §4 / §5).

> Upstream sources are unpacked in place under `3rdpty/*/local/` on the development machine, and
> **that directory does not enter the repo** (`.gitignore:30`).
> The "full text source" column below names the members inside each upstream `tar.gz` — **those
> packages stopped being version-controlled at `a8a994f`** (provide them yourself after a clone, see
> the manifest and sha256 in `3rdpty/README.md`); the same texts that **are** obtainable inside the
> repo live in `licenses/`.

## 1 · Link-time (seven)

Measured with `nm -D --defined-only bin/libalx*.so`: all seven are present as **defined
symbols** (`ZSTD_*` / `sqlite3*` / `jpeg*` / `pcre2*` / `LZ4_*` / `zlib*` in `libalxcore.so`,
OpenSSL in `libalxcomm.so` -- re-run the command for the counts, which move with the version):

| Library | Version | License | Full text source (in-repo) |
|---|---|---|---|
| zstd | 1.5.7 | BSD-3-Clause (GPL-2 offered as an alternative) | `3rdpty/zstd/zstd-1.5.7.tar.gz` → `zstd-1.5.7/LICENSE`, `COPYING` |
| SQLite3 | 3.50.4 | public domain | upstream ships no license file ⇒ see §3 |
| OpenSSL | 3.6.3 | Apache-2.0 | `3rdpty/openssl/openssl-3.6.3.tar.gz` → `LICENSE.txt` |
| libjpeg-turbo | 3.1.90 | IJG + BSD-3-Clause + zlib | `…libjpeg-turbo-3.1.90.tar.gz` → `LICENSE.md`; **the IJG main license → `README.ijg`** |
| PCRE2 | 10.48 | BSD-3-Clause **WITH** PCRE2-exception | `3rdpty/pcre2/pcre2-10.48.tar.gz` → `LICENCE.md`, `COPYING` |
| LZ4 | 1.10.0 | BSD-2-Clause | `3rdpty/lz4/lz4-1.10.0.tar.gz` → `lib/LICENSE` |
| zlib | 1.3.2 | zlib | `3rdpty/zlib/zlib-1.3.2.tar.gz` → `LICENSE` |

**The repo-root `licenses/` is the copy that ships with the release package**, 10 files in all: the
full text of each library above, plus **`ijg.txt`** (the IJG main license — libjpeg-turbo's
`LICENSE.md` only points at it, and the tar cannot be read from inside the package), **`libspng.txt`**
(the libspng full text, see below), **`divsufsort.txt`** (see below) and **`sqlite3.txt`** (the §3
statement). `bash/package.sh` and `msvc/BuildAll/Pack.ps1` copy `licenses/` and this file into the
package root.

**Nested licenses** (counted in as well):

- **divsufsort** (MIT, `Copyright (c) 2003-2008 Yuta Mori`) — inside zstd's `lib/dictBuilder/`,
  **compiled into `bin/libalxcore.a` / `bin/libalxlib.a`** (`nm` shows `T divsufsort`). Full text in
  `licenses/divsufsort.txt`
- **libspng** (BSD-2-Clause, Randy408) — inside libjpeg-turbo's `src/spng/`, compiled into the static
  archive. Full text in `licenses/libspng.txt`; it also embeds a copy of zlib
  (`src/spng/zlib/LICENSE`) and a copy of libpng (`src/spng/libpng-LICENSE.txt` — **libpng is not
  compiled**, zero `png_` symbols)
- libjpeg-turbo's `src/md5/` uses Colin Plumb's public-domain implementation, declared in a source
  comment only
- PCRE2 bundles sljit (BSD-2-Clause, its JIT backend) — `pcre2-10.48/deps/sljit/LICENSE`; **not
  compiled in this tree** (see below)

**The PCRE2 JIT boundary**: this tree's PCRE2 is built with JIT **off** (`--enable-jit` is off by
default; `3rdpty/pcre2/local/configure.log` records it) and `pcre2_jit_compile` is **never called**,
so sljit **compiles into nothing** — zero `sljit` symbols in the archives. The 11 `pcre2_jit*`
symbols in `bin/libalxlib.a` are that no-JIT build's stubs (they return the no-JIT error), and 0 of
them enter `bin/libalx*.so` either. No sljit text has to accompany any deliverable; it would start
to matter only if a rebuild turns JIT on.

| `3rdpty/openssl/include-msvc/openssl/configuration.h` (OpenSSL 3.6.3, generated by its own build) | Apache-2.0 (as OpenSSL, §1) | `licenses/openssl.txt` |

Attribution: the font's own name table says `Copyright 2014-2021 The Fira Code Project Authors`,
while the upstream repo's license file says `Copyright (c) 2014, The Fira Code Project Authors` —
the same rights holder, a different year range.

The font is compiled into the Lza application binary through `example/Lza/src/res/Alexis_Lza.qrc`.
Lza is built by `BUILD_EXAMPLE_LZA` (default ON), but `bash/package.sh` passes
`-DBUILD_EXAMPLES=OFF` ⇒ **it does not enter the release package, it is distributed with the source
repo only**.

`configuration.h` is not in the upstream tarball — OpenSSL's own build generates it — and it is
checked in so the MSVC projects compile against the same configuration the MSVC archives were
built with (`msvc/AlxComm/AlxComm.vcxproj` puts its include path ahead of `openssl/include/` on
purpose; see `3rdpty/README.md`). Like the font, it ships with the source repo only, not with
the release package.

Lza's icons (`icon.ico` / `icon.png`) and `doc/architecture.svg` are this project's own work and are
not part of this inventory.

## 4 · Source distribution packages

`3rdpty/` holds 7 upstream `.tar.gz` packages (**not version-controlled**, provide them yourself after a clone):

| Package | License |
|---|---|
| `lz4-1.10.0.tar.gz` | the core is BSD-2-Clause; **`programs/` is GPL-2.0-or-later**, and `lib/dll/example/Makefile` is GPL too |
| `openssl-3.6.3.tar.gz` | Apache-2.0 (the package's `external/`, `test/certs/` also carry GPL/Artistic, Bouncy Castle and others, none of which take part in the build) |
| `sqlite3-3.50.4.tar.gz` | **locally repacked** (not an upstream release, and the package carries no license file) ⇒ the public-domain statement of §3 applies |
| the other four | as in §1 |

**The build takes only each package's core directory** (`lib/` or its equivalent — every link line
refers to `${…DIR}/lib/*.a`); lz4's `programs/` (GPL) takes no part in the build and is not part of
the MIT work either — the two are distributed side by side in the repo without deriving from each
other, which is mere aggregation.

**No patches are shipped** ⇒ Apache-2.0 §4(b) ("mark modified files") is not triggered. (The build
scripts under `3rdpty/openssl/scripts/` do edit the local build tree in place, but they land in
`3rdpty/*/local/`, which `.gitignore` blocks — never distributed.)

## 5 · Windows libraries provided at build time

`3rdpty/*/lib/` holds 9 Windows `.lib` files (about 93 MB in all; **not
version-controlled**, provide them yourself after a clone). They are the MSVC build products of
**five** of the seven libraries in the table above -- zstd and pcre2 ship none, so the MSVC build
needs those built first (`3rdpty/README_msvc.md`). Seven are static archives and two
(`jpeg.lib`, `turbojpeg.lib`) are libjpeg-turbo's import libraries for its shared build; the six
the projects link are `turbojpeg-static.lib`, `liblz4_static.lib`, `sqlite3.lib`, `zlib.lib`
(AlxCore) and `libcrypto.lib`, `libssl.lib` (AlxComm). The other three (`jpeg.lib`,
`jpeg-static.lib`, `turbojpeg.lib`) are referenced by nothing. Their licenses are still
covered by the §1 entries (BSD / Apache-2.0 / IJG / zlib / public domain all permit binary
distribution and require the notice to accompany it — which `licenses/` does, shipped with the
package).

**Qt is not distributed**: `example/Lza` links Qt6 (LGPLv3) through `find_package(Qt6 6.5 REQUIRED)`,
and the repo holds no Qt binary. Should an Lza product ever be shipped outside, the LGPLv3
obligations take effect immediately.

## 6 · OpenSSL is incompatible with GPLv2-only

`ALXCOMM_TLS` defaults to **ON** (`CMakeLists.txt:62`) ⇒ a default build's deliverables link
Apache-2.0 OpenSSL, and **Apache-2.0 is incompatible with GPLv2-only** (it is compatible with
GPLv3).

OpenSSL enters through the `alxcomm` module alone: a downstream that needs GPLv2-only compatibility
rebuilds with `-DALXCOMM_TLS=OFF` and gets products without OpenSSL.
